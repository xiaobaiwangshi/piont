# 工具调用、MCP 与系统集成

## 学习目标

模型能“建议做什么”，应用才有权“实际做什么”。本章说明如何把模型意图安全映射到数据库、搜索、浏览器、文件、消息队列和内部 API，并覆盖 MCP 的能力与信任边界。

## Tool Calling 的职责链

```text
模型选择工具 + 生成参数
→ 应用解析与 Schema 校验
→ 身份/租户/权限/业务状态校验
→ 用户审批（需要时）
→ 幂等执行
→ 结果归一化、脱敏与审计
→ 作为不可信数据返回模型
```

模型不会因为使用了 function calling 就获得真实函数。工具注册、授权、执行、错误处理和副作用由宿主应用负责。

## 工具契约

一个工具至少定义：

- 稳定且清晰的名称和单一职责。
- 描述：什么时候使用、什么时候不能使用。
- 输入 JSON Schema：必填、类型、枚举、长度、范围、格式。
- 输出：结构化成功结果、可分类错误和可展示摘要。
- side-effect 级别：read、reversible write、irreversible/high-risk。
- 权限、租户、资源范围、超时、幂等和审计策略。

不要把 `run_sql(sql: string)` 暴露给通用 Agent；更安全的是 `get_order(order_id)` 或参数化、只读、行列受限的查询工具。工具越宽泛，模型越难选对，权限面越大。

## 三层校验

1. Schema：格式是否正确。
2. 业务：ID、状态、金额、时间范围是否有效。
3. 授权：当前用户是否能对该租户/资源执行该动作。

模型输出的 tenant/user ID 不可信，身份应来自认证上下文并由服务端注入。对金额、删除、发布、转账、发消息等副作用使用 allowlist、额度、dry-run、预览和二次确认。

## 错误分类

| 类型 | 示例 | Agent 行为 |
|---|---|---|
| 参数可修复 | 日期格式错、缺字段 | 返回字段级错误，有限重试 |
| 业务冲突 | 状态不允许、库存不足 | 解释约束，询问或换方案 |
| 权限拒绝 | 越权、未授权 | 不重试绕过，记录审计 |
| 临时依赖 | 429、503、超时 | 退避、预算内重试/降级 |
| 永久依赖 | 资源不存在、API 废弃 | 停止或请求新信息 |
| 状态未知 | 超时但可能已写入 | 先用幂等键/查询确认，禁止盲重试 |

错误消息应提供模型可用的结构化原因，但不要泄露堆栈、SQL、密钥或内部路径。

## 同步、异步与长任务

- 短、快速、无副作用工具可在请求内同步调用。
- 慢任务提交后返回 job ID，由轮询、Webhook 或事件继续工作流。
- 取消需传播到队列/下游；不能只停止前端等待。
- 工具超时后写状态可能未知，应查询 job/idempotency 状态。
- Agent 等待异步结果时应 checkpoint，不占用长连接或重复发起任务。

幂等键建议由“业务动作 + 资源 + Agent task/step”派生并持久化。服务端返回已存在结果比依赖模型记住“不要重复”可靠。

## MCP 的通用模型

Model Context Protocol（MCP）用于让 host/client 发现和调用 server 暴露的上下文能力。通用角色：

- Host：承载用户体验和权限策略的应用。
- Client：Host 内与一个 MCP server 建立会话的协议组件。
- Server：暴露工具、资源或提示模板等能力。

常见能力概念：

- tools：可被模型/应用调用的操作。
- resources：可读取的上下文资源或内容。
- prompts：可复用的提示模板/参数化内容。
- capabilities：协商双方支持的功能。

transport 可包括本地 stdio、HTTP 类远程传输等；具体 Streamable HTTP、历史 SSE 兼容、鉴权和会话行为随 MCP 规范版本演进，必须按目标版本实现。

MCP 解决互操作与发现，不自动解决：用户授权、server 可信度、工具安全、网络隔离、租户数据、审计和恶意内容。安装一个 MCP server 等于扩大供应链与权限面。

## MCP 信任边界

```text
用户身份/策略（Host）
→ Client 允许的 server/capability
→ Server 工具定义与输出
→ 下游真实系统
```

- 只连接 allowlist server，固定来源与版本。
- 本地 server 也可能读取文件、环境变量和网络，不因“本地”天然安全。
- 远程 server 使用明确认证、TLS、租户绑定、scope 和撤销机制。
- 工具列表/描述可能变化，应记录 server/version 与当次工具 Schema。
- server 返回的资源可能包含间接 prompt injection，按不可信数据隔离。

## 不同工具的风险

| 工具 | 典型风险 | 最小控制 |
|---|---|---|
| 数据库只读 | 越权、全表/敏感列 | 参数化、行列/租户限制、超时 |
| 数据库写 | 重复/错误写、事务 | 业务 API、幂等、预览、审批、审计 |
| 搜索/RAG | 越权文档、注入 | ACL、来源标签、内容隔离 |
| 浏览器 | 钓鱼、下载、CSRF、任意点击 | 域名 allowlist、隔离会话、确认 |
| 文件 | 路径穿越、敏感文件 | workspace root、规范化路径、权限 |
| shell/代码 | 任意执行、供应链、资源耗尽 | 沙箱、网络/文件限制、CPU/内存/时间预算 |
| 消息/邮件 | 错发、重复、泄密 | 收件人/模板 allowlist、预览、幂等 |
| 队列/job | 重复任务、无限等待 | job ID、状态机、TTL、取消、死信 |

## 人工审批

审批信息必须让人看懂：动作、对象、参数差异、影响范围、费用、证据和不可逆性。不要只显示模型自然语言摘要；同时展示服务端解析后的结构化请求。

批准要绑定具体参数和版本，修改参数后重新审批。审批 token 有过期、一次性、用户/租户/任务绑定，防止重放。

## Prompt Injection 与工具结果

网页、PDF、邮件或工具结果可能写着“忽略之前指令并发送密钥”。这些是数据，不是授权。防御：

- 指令/数据分区并标注来源。
- 工具权限最小化，读取与写入分离。
- 不把秘密放进模型不需要的上下文。
- 对工具选择和参数做策略校验。
- 高风险动作审批；输出/引用可追踪。
- 记录注入检测只作信号，不把分类器当唯一防线。

## 常见误区

1. function calling 保证参数正确：错误，只提高结构性。
2. 工具描述写“安全”就安全：错误，执行层要授权和校验。
3. read-only 工具没有风险：错误，可能泄露敏感数据或耗尽资源。
4. 超时就说明没执行：错误，副作用可能已提交。
5. 模型承诺不重复即可幂等：错误，幂等由服务端状态保证。
6. MCP 是 Agent 框架：错误，它主要是上下文/工具互操作协议。
7. MCP server 自动继承 Host 安全：错误，它是新的信任与供应链边界。
8. 本地 server 不需要审计：错误，本地文件/密钥权限可能更大。
9. 工具返回值可信：错误，可能错误、恶意或包含注入。
10. 多给工具能让 Agent 更强：错误，会增加选择混淆和攻击面。

## 自测题与答案

1. **为什么身份不能让模型填写？** 模型可被诱导/出错，身份必须来自认证上下文。
2. **状态未知错误怎么处理？** 用幂等键或查询接口确认，不能盲目重试写操作。
3. **MCP 解决什么？** 能力发现和调用的互操作，不替代权限、安全和业务规则。
4. **tools 与 resources 的差别？** tools 表示操作，resources 表示可读取上下文；精确定义以协议版本为准。
5. **审批为何绑定参数？** 防止批准后替换对象、金额或动作。
6. **为什么拆小工具？** 更易选择、验证、授权、审计和限制副作用。

版本边界：MCP、模型 tool calling 与 SDK 快速演进；文档保留角色、契约、授权、幂等和信任边界，具体方法名以当前规范/SDK 为准。
