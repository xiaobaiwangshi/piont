## 使用方式

`raw_llm/` 和 `raw_llm_doc/` 是只读原始资料，`knowledge-base/09-AI与大模型/` 是学习入口。原始资料用于追溯、补图和交叉核对，不按文件顺序逐篇学习，也不把旧命令直接用于当前环境。

本次盘点基线（2026-08-16）：

- `raw_llm/`：838 个文件，约 145MiB；其中 96 个 Markdown、710 个 PNG，另有 PDF/WebP/JPEG/GIF 等。
- `raw_llm_doc/`：103 个文件，约 64MiB；其中 92 个 PDF，多为 2023—2024 年面试专题。
- 两处 PDF 与 Markdown 主题高度重复；PDF 只做补缺和交叉核对。
- `raw_llm_doc/` 中 `main.py`、IDE/依赖等附属文件不作为 AI 知识来源。

## 稳定知识

可长期保留并用官方/论文校正：

- token、embedding、自回归目标、Attention、残差、Norm、FFN。
- 交叉熵、采样、上下文与 KV Cache 的数量级关系。
- RAG 的 ingest/retrieve/rerank/generate/evaluate 分层。
- Schema 校验、最小权限、幂等、状态机、checkpoint 和补偿。
- precision/recall、MRR/nDCG、离线/在线评测和数据泄漏原则。
- 数据并行、张量/流水线并行和显存构成等基础机制。

稳定不等于所有讲法都正确；原始资料中的固定数值和绝对结论仍需核对假设。

## 快速变化内容

以下信息必须附产品/规范/模型/框架版本和日期：

- 模型上下文长度、价格、参数、Tokenizer、许可证和 API 字段。
- tool calling/structured output、流式、缓存和限流语义。
- MCP transport、capability、鉴权和 SDK API。
- LangChain/LangGraph 等 Agent 框架的类名、memory/checkpoint 行为。
- vLLM、TGI、TensorRT-LLM、DeepSpeed、FSDP、PEFT 配置和兼容矩阵。
- 量化格式、GPU kernel、吞吐/显存数字和硬件建议。
- benchmark 排名、模型家族对比和“最佳实践”。

看到“无限长度”“提升 46%”“只需多少显存”等标题时，先查论文/测试的模型、硬件、数据、长度、batch、基线和质量代价。

## 历史材料的保留价值

- BERT、Word2Vec、CNN/RNN、jieba、词性/句法帮助理解 NLP 演进，但不是 Agent 主线。
- LLaMA 2、ChatGLM3、旧 LangChain 和早期推理框架资料可理解设计背景，不作为当前 API 手册。
- 面试题适合发现概念缺口，不适合当唯一事实来源；问答可能简化条件或混合版本。
- 旧训练/部署命令只读，不在未固定环境和版本时执行。

## 纠错规则

1. 先区分稳定原理、实现选择、版本事实和测量结果。
2. 原理优先查原论文/教材；协议/API 查官方规范和目标版本文档。
3. 数字必须附模型、精度、长度、batch、硬件、软件和测量口径。
4. 多来源冲突时保留证据和版本，不强行合并成无条件结论。
5. AI 对话与面试答案只作线索，不能覆盖官方定义和可复现结果。

## 推荐学习顺序

```text
00 转型路线
→ 01 大模型基础 + 07/10 核心机制
→ 02 模型接口
→ 03 RAG/记忆
→ 04 工具/MCP
→ 05 Agent 架构 + 07/11 运行机制
→ 06 生产可靠性
→ 07 评测安全治理
→ 08 训练与部署选学
```

对十年全栈开发者，重点不是重学 Web/数据库，而是把现有的 API、状态、队列、幂等、权限、可观测性能力迁移到模型不确定性和工具副作用上。

## 资料验收清单

- 是否能指出每个结论是原理、版本事实还是测量结果？
- 是否能解释 Agent 状态、终止、幂等、恢复和权限边界？
- 是否用业务结果而不是主观观感评测？
- 是否把 RAG 文档、模型输出和工具结果视为不可信输入？
- 是否记录 prompt/model/tool/index/eval 版本？
- 是否在决定微调或自托管前建立 API/RAG 基线和成本数据？

版本边界：本索引反映 2026-08-16 的本地资料盘点；原始目录新增或删除文件后应重新统计，并只更新本导读和对应知识章，不改原文件。
