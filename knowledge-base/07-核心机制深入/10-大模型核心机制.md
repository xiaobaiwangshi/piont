# 大模型核心机制

## 阅读边界

基础学习顺序见[AI 与大模型基础、Transformer](../09-AI与大模型/01-AI与大模型基础Transformer.md)。本章集中推导张量形状、复杂度和内存数量级，帮助 Agent 工程师理解上下文、模型接口和部署约束；不展开训练框架实操。

## 从 token 到 logits

设 batch 为 B，序列长度 L，隐藏维度 d，词表 V：

```text
token IDs:      [B, L]
embedding:      [B, L, d]
hidden states:  [B, L, d]
logits:         [B, L, V]
```

生成时通常只需要最后位置的 logits 选择下一个 token。训练时可在多个目标位置计算交叉熵。

词嵌入参数量约 `V×d`。例如词表 100000、d=4096，仅 embedding 就约 4.096 亿参数；若与输出头权重共享则不再另计一份，否则还需同量级投影参数。

## Scaled Dot-Product Attention

单层输入 X 经过线性投影：

```text
Q = XWq
K = XWk
V = XWv
Attention(Q,K,V) = softmax(QKᵀ / sqrt(d_head) + mask) V
```

多头常拆为：

```text
Q: [B, query_heads, L, head_dim]
K: [B, kv_heads,    L, head_dim]
V: [B, kv_heads,    L, head_dim]
```

MHA 通常 `kv_heads=query_heads`；MQA 可让所有 query head 共享一组 K/V；GQA 使用若干组 K/V。具体广播和布局由实现决定。

除以 `sqrt(d_head)` 是为避免点积方差随维度增大导致 softmax 过度饱和。causal mask 把未来位置分数置为无法被选择的值。

## Attention 复杂度与长上下文

标准 Attention 的 QKᵀ score 形状约 `[B, heads, L, L]`，时间/中间矩阵随 `L²` 增长，V 加权还与 d 相关。序列翻倍时 score 元素约四倍。

例如 B=1、32 heads、L=8192，仅 score 元素为：

```text
32 × 8192² ≈ 21.47 亿元素
FP16/BF16 原始字节约 4GiB
```

这不是完整实际显存：FlashAttention 可通过分块避免物化完整 score，训练还需反向与其他激活。它说明为什么实现、精度和内存访问方式决定可支持长度。

长上下文还有有效性边界：位置外推、训练长度、信息分布、检索干扰和 lost-in-the-middle 会让“允许输入”不等于“可靠使用”。

## 位置、残差与 Norm

RoPE 把与位置相关的旋转应用于 Q/K，使相对位置信息进入点积。通过缩放等方式扩展长度可能影响短/长位置表现，必须按目标模型和评测验证。

Residual 形成信息与梯度的主通道；Pre-Norm/Post-Norm 决定 Norm 相对子层的位置，训练稳定性和深度行为不同。RMSNorm 主要按均方根缩放，不减均值；它不是 LayerNorm 的同名实现。

FFN 常把 d 扩展到更高维再投影回 d，并使用 GELU、SiLU/SwiGLU 等激活。模型大量参数位于 FFN，而不仅是 Attention。

## 训练显存数量级

训练显存可拆为：

```text
权重 + 梯度 + 优化器状态 + 激活 + 临时缓冲 + 通信/碎片
```

以 P 个参数、混合精度 Adam 类训练粗估：低精度权重约 2P bytes，梯度约 2P，FP32 master weight/一阶/二阶状态可能各约 4P，总静态项可到约 16P bytes，具体实现可能保存不同副本。

7B 参数按 16 bytes/参数粗估静态项约 112GB，尚未含激活。ZeRO/FSDP 可跨设备分片权重、梯度和优化器状态；activation checkpointing 用重复计算换激活显存；offload 用主存/存储带宽换 GPU 显存。固定“每参数 16 bytes”必须绑定优化器、精度和框架。

## LoRA 参数量

原矩阵 `W ∈ R^(d_out×d_in)` 冻结，LoRA 学习低秩增量 `BA`，秩 r：

```text
A: [r, d_in]
B: [d_out, r]
trainable_params = r(d_in + d_out)
```

若 `d_in=d_out=4096`、r=16，一个目标矩阵新增 `16×8192=131072` 参数，而原矩阵约 1678 万参数。总量还要乘目标层/矩阵数。低秩减少可训练参数，不保证数据少、任务不匹配或目标层错误时仍有效。

## KV Cache

自回归 decode 保存历史 token 的 K/V，避免每步重算所有历史。未考虑量化、对齐和额外元数据时：

```text
KV bytes ≈ 2 × layers × tokens × kv_heads
           × head_dim × bytes_per_element × batch
```

假设 32 层、4096 tokens、8 KV heads、head_dim=128、BF16 2 bytes、batch=1：

```text
2 × 32 × 4096 × 8 × 128 × 2 ≈ 512MiB
```

若是 32 KV heads则约 2GiB。并发、最大序列预留、块碎片和多副本会继续放大。PagedAttention 类方法把 KV 分块管理，减少连续预留和碎片，不消除 KV 随 token/并发增长。

## Prefill 与 Decode

- Prefill：处理完整输入，矩阵规模大、并行度高，通常更偏计算密集；决定 TTFT 的重要部分。
- Decode：每步生成少量 token，反复读取权重与 KV，常更受内存带宽、调度和小批次影响；决定 TPOT/ITL。

Continuous batching 动态把不同请求的 prefill/decode 合批，提高吞吐但可能增加排队或单请求延迟。优化目标必须绑定 SLO、输入/输出长度分布和硬件。

## 量化边界

量化降低每参数 bytes 和带宽，可作用于权重、激活、KV Cache。INT8、INT4、FP8 等名称不足以说明质量：校准数据、group size、scale、outlier、kernel 和硬件支持都会影响结果。

模型文件大小粗估为 `P×bits/8`，但运行显存还包含反量化/工作区、KV Cache、图和服务缓冲。7B 的 4-bit 权重理论约 3.5GB，不等于服务只需 3.5GB 显存。

## Agent 工程的结论

- 长 prompt 同时增加 prefill 延迟、费用和 Attention/缓存压力。
- MQA/GQA 对高并发长对话服务特别重要，因为 KV Cache 更小。
- 输出 token 常按序列 decode，长回答增加 TPOT 累积和连接占用。
- API 模型隐藏底层实现，但 token、上下文、延迟和成本规律仍存在。
- 任何显存/吞吐数字都要注明模型架构、精度、输入输出分布、batch、版本与硬件。

## 自测答案

1. **L 翻倍为何标准 score 约四倍？** score 包含每个 query 位置与每个 key 位置的组合，即 L×L。
2. **FlashAttention 是否把理论 Attention 变 O(L)？** 它主要通过分块与 IO-aware 计算避免大中间矩阵，不能笼统宣称所有计算都线性。
3. **GQA 如何降低 KV？** kv_heads 少于 query_heads，缓存 K/V 头数下降。
4. **LoRA r 越大越好吗？** 容量提高但参数、显存和过拟合风险增加，需任务评测。
5. **权重能放入 GPU 为何仍可能 OOM？** 还有 KV、激活、workspace、通信和碎片。
6. **prefill 与 decode 应用指标？** prefill 影响 TTFT，decode 单 token 间隔影响 TPOT，二者共同形成端到端延迟。

版本边界：模型配置字段、FlashAttention、量化 kernel 和服务框架快速变化；公式描述稳定数量级，实际值以模型 config、服务版本和观测为准。
