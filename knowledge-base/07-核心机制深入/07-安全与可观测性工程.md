# 安全与可观测性工程

## 从威胁模型开始

安全不是罗列加密算法。先回答：保护什么资产、谁可能攻击、从哪里进入、影响多大、信任边界在哪。对数据流逐段做 STRIDE 等威胁分析：伪造、篡改、抵赖、信息泄露、拒绝服务、权限提升。

## 密码与加密

- 密码存储：Argon2id/bcrypt/scrypt + 每用户随机 salt；不能可逆加密，也不能直接 MD5/SHA。
- 传输：TLS 验证身份并协商会话密钥。
- 静态数据：信封加密，数据密钥加密内容，KMS 主密钥包装数据密钥。
- 完整性：MAC/AEAD；只加密不认证可能被篡改。
- 签名：私钥签名、公钥验证，用于来源与完整性，不用于保密。

Nonce/IV 的唯一性要求取决于算法。不要自己组合加密原语；使用成熟 AEAD（如 AES-GCM/ChaCha20-Poly1305）和官方库。

## 授权模型

- RBAC：用户→角色→权限，适合组织权限。
- ABAC：依据用户、资源、环境属性决策，灵活但规则复杂。
- Resource ownership：每次访问都校验资源归属，防 IDOR。

后端必须执行授权；隐藏前端按钮不是安全控制。管理员、服务账户和运维脚本同样使用最小权限。

## 供应链与运行环境

- 锁定依赖版本并持续漏洞扫描。
- 构建产物可追溯，生产不临时在线安装依赖。
- 容器使用非 root、只读文件系统和最小 capability。
- Secret 不放镜像、环境日志或命令行历史。
- 发布需要签名、审批、回滚与审计。

## Metrics 的数学边界

Counter 单调累加，重启归零；Gauge 可升降；Histogram 按桶统计分布；Summary 通常在客户端计算分位数。

分位数不能简单平均。多实例聚合 p99 应使用可聚合 histogram；桶边界要覆盖真实 SLO。平均延迟会掩盖少量超慢请求。

## Trace 与采样

Trace 由 span 构成父子关系，记录服务、操作、时间和状态。头部采样在请求开始决定，成本可控但可能漏错误；尾部采样看到完整结果后保留慢/错请求，能力强但基础设施更复杂。

日志、指标和 Trace 通过 trace_id、service、版本和部署环境关联。高基数业务值放日志/Trace，不随意放 Prometheus label。

## SLO 推导

若 30 天有 1000 万次有效请求，SLO 99.9%，错误预算为：

```text
10,000,000 × (1 - 0.999) = 10,000 次失败
```

使用 burn rate 告警同时覆盖“短时间快速烧完预算”和“长时间缓慢超标”，比固定 5xx 阈值更贴近用户目标。

## 事件响应

1. 分级、指定指挥者和沟通频道。
2. 保存证据并控制影响。
3. 轮换泄露凭证、阻断入口、回滚。
4. 确认攻击者持久化和横向移动范围。
5. 恢复、持续监控、依法合规通知。
6. 无责复盘并验证改进。

## 验证实验

- 构造越权访问，证明资源归属校验有效。
- 轮换一枚测试密钥，验证新旧版本平滑过渡和撤销。
- 用相同流量比较平均值与 p95/p99。
- 注入 1% 慢请求，验证 Trace 采样和 SLO 告警能发现。
