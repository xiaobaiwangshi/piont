# 音视频系统核心机制

## 从信号到压缩

视频帧把连续光信号采样为像素；音频把声波按采样率和位深离散化。压缩利用：

- 空间冗余：同一帧相邻像素相近。
- 时间冗余：相邻帧大量内容相同。
- 感知冗余：人眼/耳不敏感的信息可量化丢弃。

## 色彩

RGB 适合显示，编码常使用 YCbCr。4:2:0 减少色度采样，适合消费视频；文字/UI 细边缘可能出现色彩损失。位深 8-bit/10-bit 决定每通道量化级数；HDR 还涉及色域、传递函数和元数据，不等同于“更亮”。

像素格式、色彩范围、色彩空间标记错误会导致偏色或灰阶异常，转码不能只看分辨率。

## 编码器决策

编码器通常进行块划分、帧内/帧间预测、变换、量化和熵编码。CRF 主要控制质量，preset 控制编码器搜索努力，码率控制模型用 VBV 的 maxrate/bufsize 约束短时输出。

直播常用受约束码率以保护网络；离线点播更适合按质量编码后生成多梯度。硬件编码速度快、功耗低，但相同码率画质可能不同，必须以目标设备实测。

## 音频

- 采样率决定可表示频率上限，理论上约为采样率一半。
- 位深影响量化动态范围。
- MP3/AAC/Opus 是有损编码；FLAC 是无损。
- 把低码率有损音频重新编码为高码率不会恢复细节，只会再损失或增大文件。

音量、响度和峰值不同。内容平台可用 LUFS 做响度规范，并防止滤镜放大后 clipping。

## ABR 自适应码率

```text
源文件
→ 统一关键帧时间轴
→ 多分辨率/码率编码
→ 分片
→ master playlist/manifest
→ CDN
→ 播放器按吞吐和缓冲切换
```

所有梯度必须关键帧对齐，否则切换时可能黑屏或跳帧。码率阶梯应按内容复杂度做 per-title/per-shot 评估，不只固定 360p/720p/1080p 表。

## 播放延迟组成

DNS/TLS、manifest、首分片下载、解复用、解码和缓冲共同决定首播时间。HLS 分片越短，延迟和切换粒度更好，但请求数、封装开销和 CDN 压力更高。低延迟 HLS 使用 partial segment 等机制，需要全链路支持。

## DRM 边界

DRM 把内容密钥交给许可证服务和受保护解密环境，支持设备绑定、过期、输出保护等策略。它能显著提高批量下载和直接提 key 的成本，但不能阻止摄像、系统级攻破或授权账户录屏。

安全体系还需短期授权、账号风控、并发设备限制、动态水印、泄露追踪和下架响应。

## 验证指标

- VMAF/SSIM/PSNR：画质参考，不能完全替代主观观看。
- 首帧时间、卡顿率、平均码率、清晰度切换。
- 编码速度、CPU/GPU、产物体积和失败率。
- 音频响度、峰值、同步偏差。

同一源素材建立基准集，再比较编码参数；只凭单段动画或静态画面得出的结论不能推广到所有内容。
