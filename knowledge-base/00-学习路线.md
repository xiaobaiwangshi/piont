# 学习路线

## 目标

这套路线不是把术语背一遍，而是建立一条能解释真实 Web 系统的因果链：硬件提供资源，操作系统管理资源，网络传递请求，算法组织计算，服务端程序处理业务，组件保存和传递状态，架构解决规模与故障问题。

正文已融合两类来源：`raw_doc_` 提供不随版本轻易变化的原理和问题模型，开放教材、RFC 与官方文档负责纠错和补充现代版本。资料本身不是必读顺序，按本路线进入主题即可。

## 第一阶段：四大基础

### 1. 计算机组成原理

掌握 CPU、缓存、内存、磁盘、总线、指令执行和 I/O。完成后应能解释：

- 为什么内存数据库通常比磁盘查询快。
- 为什么顺序 I/O、批处理和局部性有效。
- CPU 使用率、负载、上下文切换分别说明什么。
- Cache line、OS page、数据库页和文件系统块为什么不能混用。

### 2. 操作系统

掌握进程、线程、虚拟内存、文件系统、系统调用、I/O 多路复用和资源调度。完成后应能解释：

- Nginx worker、PHP-FPM worker 与 Go goroutine 的区别。
- `epoll` 为什么适合大量连接，但不能让业务计算免费。
- OOM、僵尸进程、文件描述符耗尽如何产生。

### 3. 计算机网络

掌握 IP、ARP、路由、TCP、UDP、DNS、TLS、HTTP。完成后应能从域名输入一路追踪到服务响应，并区分 502、504、连接超时和读取超时。

必须会计算滑动窗口、`rwnd/cwnd/flight_size`、慢启动和带宽时延积，并用抓包/`ss` 验证，而不是只背“三次握手、四次挥手”。

### 4. 数据结构与算法

掌握复杂度、数组、链表、哈希表、树、堆、图、排序、搜索、分治、贪心、动态规划。重点不是手写所有算法，而是能为索引、缓存、调度和业务规则选择正确结构。

## 第二阶段：Web 服务端基础

按以下顺序学习：

1. HTTP 请求、状态码、缓存、Cookie、跨域与幂等。
2. Nginx 静态资源、反向代理、FastCGI、负载均衡。
3. PHP-FPM 请求模型与 PHP 语言；Go HTTP/Gin 与并发模型。
4. MySQL 表、索引、事务；Redis 数据结构与缓存模式。
5. Linux 日志、进程、CPU、内存、磁盘和网络排查。

## 第三阶段：组件与工程化

- Elasticsearch：全文检索、倒排索引、分片与副本。
- Kafka：日志模型、分区、副本、消费者组和消息语义。
- 任务队列：异步化、削峰、重试、幂等和死信。
- 可观测性：指标、日志、链路、告警和 SLO。
- 安全：认证授权、输入验证、密钥管理和最小权限。

## 第四阶段：架构能力

先量化问题，再引入架构：

- 单机资源不够：先查瓶颈，再纵向或横向扩展。
- 读压力高：索引、缓存、只读副本或搜索引擎。
- 写入峰值高：批处理、队列、背压和限流。
- 依赖不稳定：超时、重试、熔断、隔离和降级。
- 不能停机：冗余、健康检查、故障转移和灰度发布。

## 第五阶段：AI Agent 转型

面向已有全栈经验的开发者，大模型基础是必修，模型训练是选学。按以下顺序：

1. [AI 与大模型基础、Transformer](09-AI与大模型/01-AI与大模型基础Transformer.md)：理解 token、embedding、Attention、训练阶段和生成边界。
2. [LLM 应用基础与模型接口](09-AI与大模型/02-LLM应用基础与模型接口.md)：掌握消息、上下文、结构化输出、流式接口、成本和错误处理。
3. [RAG、上下文与长期记忆](09-AI与大模型/03-RAG上下文与长期记忆.md)：构建可更新、可授权、可引用和可评测的事实链。
4. [工具调用、MCP 与系统集成](09-AI与大模型/04-工具调用MCP与系统集成.md)：把模型意图安全映射到真实 API 和数据系统。
5. [Agent 架构、编排与多 Agent](09-AI与大模型/05-Agent架构编排与多Agent.md)：用状态机和 workflow 限制自治循环。
6. [Agent 生产工程与可靠性](09-AI与大模型/06-Agent生产工程与可靠性.md)：复用分布式系统、队列、幂等、补偿、可观测性和 SLO 能力。
7. [评测、安全、成本与治理](09-AI与大模型/07-评测安全成本与治理.md)：建立发布门槛和纵深防御。

完整说明见[AI Agent 转型路线](09-AI与大模型/00-AI-Agent转型路线.md)。本阶段文档只整理知识和案例，不要求实际训练、部署模型或搭建向量库。

## 验收方式

每个主题至少完成四项：

1. 用自己的话解释原理。
2. 画出一次真实请求的数据流。
3. 做一个最小可运行案例。
4. 制造一个故障，用证据定位并恢复。

不要用“看完文档”作为验收。能预测行为、验证预测并解释偏差，才算掌握。

统一实验清单见[实验与验收清单](07-核心机制深入/09-实验与验收清单.md)，旧资料的可用主题与版本风险见[`raw_doc_` 原始资料主题索引](99-原始资料主题索引.md)。
