# 计算机组成原理

## 学习目标与阅读方式

学完本章，应能沿“数据表示 → 指令 → CPU → Cache/内存 → I/O 设备”解释程序如何运行，并能：

- 区分 ISA、微架构、操作系统和应用各自可见的边界。
- 使用 CPU 时间、CPI/IPC、Amdahl 定律、AMAT 和带宽公式完成数量级估算。
- 解释流水线、分支预测、缓存未命中、一致性、DMA 为什么影响服务端性能。
- 从 CPU、内存和 I/O 指标建立故障证据链，而不是只看使用率。

先修知识只需要二进制和基本代数。本文负责概念、计算、案例与自测；乱序执行、缓存一致性、页表、NUMA 和设备路径的实现推理见[硬件与操作系统核心机制](../07-核心机制深入/01-硬件与操作系统.md)。文中的命令和计算均为知识示例，本阶段不要求执行实验。

## 基础知识

### 数据如何表示

一个 n 位无符号整数范围是 `0 ~ 2^n-1`；常见二进制补码有符号整数范围是 `-2^(n-1) ~ 2^(n-1)-1`。补码使加减法共用硬件，但溢出后的语言语义不同：C 有符号溢出是未定义行为，Java 整数按固定位宽回绕，PHP 整数宽度受平台影响。

IEEE 754 浮点数由符号、指数和有效数构成，很多十进制小数不能被二进制有限精确表示。因此金额通常使用整数最小单位或十进制定点类型，不能用 `0.1 + 0.2 == 0.3` 判断业务金额。

- 位（bit）是二进制信息单位，字节（byte）通常为 8 bit。
- 大端把高位字节放在低地址，网络字节序使用大端；x86 常见小端。
- UTF-8 是变长编码，一个 Unicode 码点通常占 1～4 字节；码点、用户看到的字符和字节数不是同一概念。
- 对齐让对象地址满足硬件访问要求，可能用空间换更简单或更快的访问。

### 计算机的核心部件

- CPU：执行指令，包含控制单元、算术逻辑单元、寄存器等。
- 内存：保存正在运行的代码和数据，断电后通常丢失。
- 外部存储：SSD/HDD，容量大、持久化，但延迟高于内存。
- 总线与互连：在 CPU、内存和设备之间传递地址、数据和控制信息。
- I/O 设备：网卡、磁盘、显示器等，通过控制器和操作系统驱动工作。

程序大致经历“取指 → 译码 → 执行 → 访存 → 写回”。现代 CPU 会使用流水线、乱序执行、分支预测和多级缓存提升吞吐量，因此真实执行并不总是严格逐条完成。

ISA（指令集架构）定义软件能看到的指令、寄存器、异常和内存访问语义；微架构是某款 CPU 对 ISA 的具体实现，例如流水线宽度、Cache 大小和分支预测器。x86、ARM、RISC-V 是 ISA 家族，不能从 ISA 名称直接推出某款 CPU 的真实性能。

异常与中断都会改变正常控制流。异常通常由当前指令同步触发，例如缺页或除零；中断通常由定时器、网卡等外部事件异步触发。系统调用常通过受控陷入从用户态进入内核，它与设备中断不是同一件事。

### 存储层次

```text
寄存器 → L1/L2/L3 缓存 → 内存 → SSD → HDD/远程存储
更快、更小、更贵  ←→  更慢、更大、更便宜
```

局部性是缓存有效的基础：

- 时间局部性：刚访问的数据可能很快再次访问。
- 空间局部性：访问某地址后，附近地址也可能被访问。

数组顺序遍历通常比随机访问链表更适合 CPU 缓存。数据库页、Redis 紧凑编码、批量网络传输都在利用类似原理。

### 性能基本量

- 延迟：一次操作完成所需时间。
- 吞吐量：单位时间完成的操作数量。
- 带宽：单位时间可传输的数据量。
- IOPS：单位时间磁盘 I/O 次数。
- CPU 使用率：统计周期内 CPU 忙碌时间占比。

8 核机器 CPU 使用率 70%，表示平均消耗约 `8 × 70% = 5.6` 个核的计算时间，即每秒约 5.6 core-seconds；它不能直接换算成 QPS，还需要每个请求实际消耗的 CPU 时间。

### 从指令到程序耗时

一条指令通常要经过取指、译码、执行、访存和提交，但流水线会让多条指令的不同阶段重叠。程序耗时可用下面的模型拆解：

```text
CPU time ≈ instruction_count × CPI / clock_rate
```

- `instruction_count` 受算法、编译器和指令集影响。
- CPI 是平均每条指令所需周期，受缓存未命中、分支预测、数据依赖和执行端口影响。
- 主频只是一个因子；更高主频不保证更少指令或更低 CPI。

若统计口径一致，`IPC = instructions / cycles`，平均 `CPI ≈ 1 / IPC`。现代超标量 CPU 的 IPC 可能大于 1；缓存未命中或依赖停顿会使 CPI 上升。不能把某一瞬间的标称主频直接代入长期容量，还要考虑动态频率、功耗、虚拟机配额和调度时间。

优化时先判断问题来自“做了太多工作”“每条指令等待太久”还是“频率/配额受限”。同为 `O(n)` 的数组顺序扫描和链表随机访问，可能因为 Cache 与预取差异产生数量级不同的常数。

#### Amdahl 定律

若程序中比例 `p` 的部分能加速 `s` 倍，整体加速比上限为：

```text
speedup = 1 / ((1 - p) + p / s)
```

例如 80% 的耗时可并行到 8 倍，整体最多约 `1 / (0.2 + 0.8/8) = 3.33` 倍，而不是 8 倍。串行部分、通信和调度成本决定扩核上限。

#### 带宽与传输时间

```text
ideal_transfer_time = data_size / effective_bandwidth
```

若有效带宽为 2GiB/s，顺序传输 8GiB 至少约 4 秒。真实耗时还包含排队、协议、寻址、校验、并发竞争与尾延迟；标称接口带宽不是应用有效带宽。

### 不同数据块不能混为一谈

| 粒度 | 常见量级 | 决定者 | 主要作用 |
|---|---:|---|---|
| CPU cache line | 常见 64 B | 具体 CPU | 缓存一致性和硬件搬运 |
| OS page | 常见 4 KiB | 内核与体系结构 | 虚拟内存映射和回收 |
| InnoDB page | 默认常见 16 KiB | MySQL 初始化配置 | 表与索引的存储/缓存 |
| 文件系统块 | 常见 4 KiB | 文件系统格式化配置 | 空间分配与 I/O |

这些数字都不是跨平台常量。用 `getconf PAGESIZE`、`getconf LEVEL1_DCACHE_LINESIZE`、文件系统工具和数据库变量查询实际值。

## 高阶知识

### 流水线、乱序与分支

流水线让多条指令的取指、译码、执行、访存和提交阶段重叠，提高吞吐但不必降低单条指令延迟。主要障碍包括：

- 数据相关：后续指令依赖前一结果。
- 控制相关：分支方向或目标尚不确定。
- 结构冲突：多条指令争用执行单元、端口或缓存。

超标量处理器每周期可发射多条指令；乱序执行让就绪指令绕过暂时等待的指令，但通常按程序顺序提交架构可见结果，以维持精确异常。分支预测失败会丢弃错误路径上的推测结果并重新填充流水线。预测准确率、依赖链和缓存延迟都会改变 IPC，Big-O 相同不代表硬件成本相同。

### Cache 映射与平均访问时间

Cache 通常以 cache line 为传输和一致性单位，常见 64B，但必须以处理器文档为准。地址可概念性拆为：

```text
[ tag | set index | line offset ]
```

假设 32 位字节地址、32KiB Cache、64B line、8 路组相联：

```text
line 数 = 32768 / 64 = 512
set 数 = 512 / 8 = 64
offset 位 = log2(64) = 6
index 位 = log2(64) = 6
tag 位 = 32 - 6 - 6 = 20
```

这是地址字段估算，不包含有效位、脏位、替换状态和 ECC 等元数据。直接映射每个 set 只有一路；N 路组相联允许同一 set 放 N 条 line，在命中率、面积、功耗和访问延迟间取舍。

平均内存访问时间可粗略写为：

```text
AMAT = hit_time + miss_rate × miss_penalty
```

若命中耗时 1ns、未命中率 5%、额外代价 80ns，则 `AMAT = 1 + 0.05×80 = 5ns`。少量未命中就可能主导平均成本；多级缓存、并行未命中、预取和内存级并行会让真实模型更复杂。

未命中可分为首次访问、容量不足和映射冲突。硬件预取擅长规则访问，但无效预取会浪费带宽并污染 Cache。write-through 每次写都传向下层；write-back 先标脏、淘汰时写回。具体层级可能采用不同策略。

### 缓存一致性与内存可见性

多核各有私有缓存时，一致性协议维持同一物理内存位置的缓存副本关系；它不自动把任意并发程序变成线程安全。编译器、CPU 和语言运行时允许的重排，还需要原子操作、锁和语言内存模型建立 happens-before 等顺序保证。

两个线程即使修改不同变量，只要变量位于同一 cache line，也可能因所有权反复转移形成 false sharing。处理方法是先用性能证据确认，再减少共享写、按线程分片或做有依据的对齐；盲目填充会浪费缓存。

### CPU 密集与 I/O 密集

- CPU 密集：编码、压缩、加密、复杂计算。并发超过可用核心后通常只增加调度开销。
- I/O 密集：等待网络、磁盘或数据库。异步和并发能利用等待时间，但下游容量仍是上限。

FFmpeg 转码通常是 CPU 密集型；Nginx 代理大量慢连接主要是 I/O 密集型；PHP 请求往往同时包含计算和远程 I/O。

### 中断、DMA 与零拷贝

- 中断让设备通知 CPU 事件完成，不必持续轮询。
- DMA 允许设备与内存直接传输数据，减少 CPU 搬运。
- `sendfile` 等机制减少用户态与内核态间的数据复制，适合静态文件发送。

“零拷贝”不是绝对零次复制，而是减少不必要的 CPU 参与和内存复制。

CPU 通常通过内存映射 I/O 或端口 I/O 配置设备控制器；设备利用 DMA 在设备与内存之间传输数据，完成后以中断或轮询方式通知。DMA 降低 CPU 搬运，不代表 CPU、缓存一致性、IOMMU、驱动和协议栈没有成本。

### 并发与并行

- 并发：多个任务在同一时间段推进。
- 并行：多个任务在同一时刻由不同执行单元运行。

单核也能并发，但不能真正同时执行多个 CPU 指令流。线程、goroutine 数量远大于 CPU 核心数时，CPU 密集任务不会线性加速。

## 使用案例

### 粗算服务容量

若一台 8 核机器允许业务使用 70% CPU，每个请求平均消耗 0.8ms CPU 时间：

```text
可用 CPU 时间 = 8 × 0.7 = 5.6 core-seconds/s
理论 CPU 上限 = 5.6 / 0.0008 ≈ 7000 requests/s
```

这是 CPU 单因素上限，不包含锁竞争、网络、数据库、GC、队列和长尾延迟。真实容量必须压测。

### 为什么批量操作更快

一次处理多条数据可以摊薄系统调用、网络往返、协议解析和磁盘寻址成本，但批次过大会提高内存占用和长尾延迟。批量大小应通过实测选择。

### 判断扩核是否有效

若单实例 60% 时间可并行、40% 必须串行，即使并行部分获得无限核心，Amdahl 上限也只有 `1/0.4 = 2.5` 倍。扩核前应判断瓶颈是可并行计算、串行锁、内存带宽还是 I/O；否则更多线程只会增加切换与一致性流量。

## 常见问题与排查

| 现象 | 先区分 | 关键证据 |
|---|---|---|
| CPU 使用率高 | 用户计算、内核、虚拟化 steal | 每线程 CPU、热点函数、user/system/steal、指令与周期 |
| CPU 不满但延迟高 | I/O 等待、锁、内存停顿、配额 | 运行/阻塞线程、IPC、cache miss、调度与下游延迟 |
| 扩核后吞吐不升 | 串行区、共享写、带宽饱和 | 每核负载、锁等待、false sharing、内存带宽 |
| 内存带宽高 | 有效顺序访问或无效搬运 | LLC miss、工作集、访问步长、NUMA 远端访问 |
| 磁盘吞吐不高但很慢 | 小随机 I/O、队列、同步写 | IOPS、平均/尾延迟、队列深度、请求大小 |

### CPU 高

1. 用 `top`/`pidstat` 确认进程和线程。
2. 区分用户态、内核态、I/O wait 和 steal time。
3. 用语言 profiler 或 `perf` 找热点。
4. 检查忙循环、序列化、压缩、加密、GC 和锁竞争。

### 内存高

区分 RSS、虚拟内存、页缓存和 swap；不要把 Linux 的 `buff/cache` 直接判断为泄漏。结合进程指标、分配剖析和持续增长趋势定位。

### 磁盘慢

同时观察延迟、队列深度、吞吐和 IOPS。容量未满不等于 I/O 没有饱和。

## 常见误区

1. **主频越高程序一定越快**：指令数、CPI、缓存、功耗和架构都影响结果。
2. **流水线把单条指令变成零延迟**：流水线主要提高吞吐，阶段仍有延迟。
3. **IPC 永远小于 1**：超标量 CPU 在合适负载下可每周期提交多条指令。
4. **Cache line、OS page、数据库页是一回事**：它们由不同层管理，粒度与用途不同。
5. **命中率 95% 已经足够高**：要结合 miss penalty；5% 慢访问可能主导 AMAT。
6. **一致性协议等于线程安全**：程序仍需同步与语言内存模型。
7. **DMA 等于完全不使用 CPU**：配置、完成处理、驱动和协议仍消耗 CPU。
8. **零拷贝就是物理上零次复制**：通常只是减少用户态/内核态复制和 CPU 搬运。
9. **扩核可以线性加速所有代码**：串行部分、同步和带宽形成上限。
10. **CPU 使用率不高就不是硬件瓶颈**：内存停顿、I/O、配额和单核热点都可能存在。

### 自测题

1. ISA 与微架构有什么区别？
2. 8 位补码整数的范围是什么？为什么浮点金额容易出错？
3. 一段程序执行 `2×10^9` 条指令，平均 CPI 为 1.5、时钟为 3GHz，CPU 时间约多少？
4. IPC 与 CPI 是什么关系？它们在什么条件下不能用单个平均值解释全部性能？
5. 90% 的代码可加速 10 倍，按 Amdahl 定律整体加速比是多少？
6. 32 位地址、64B line、256 个 set 时，offset、index、tag 各多少位？
7. 命中时间 2ns、miss rate 2%、miss penalty 100ns，AMAT 是多少？
8. 为什么数组顺序扫描通常比链表随机访问快？
9. 缓存一致性与线程同步分别解决什么问题？
10. DMA 和零拷贝减少了什么，又没有消除什么？

### 参考答案

1. ISA 定义软件可见的指令与状态；微架构定义具体 CPU 如何流水、缓存和执行这些指令。
2. `-128~127`；很多十进制小数不能被二进制浮点有限精确表示，业务舍入会累积误差。
3. `2×10^9 × 1.5 / 3×10^9 = 1` 秒；假设频率稳定且统计的是该程序实际指令。
4. 同口径下平均 `CPI≈1/IPC`；多核、动态频率、不同阶段和等待重叠时需明确统计范围。
5. `1/(0.1+0.9/10)≈5.26` 倍，不是 10 倍。
6. offset=`log2(64)=6` 位，index=`log2(256)=8` 位，tag=`32-6-8=18` 位。
7. `2 + 0.02×100 = 4ns`；miss penalty 取“额外代价”的定义。
8. 顺序访问利用空间局部性、整条 cache line 和预取；链表节点可能分散并形成依赖链。
9. 一致性维护多核缓存副本关系；同步建立程序需要的原子性和可见顺序。
10. DMA 减少 CPU 数据搬运，零拷贝减少不必要的跨态复制；驱动、协议、页映射、设备和完成处理仍有成本。
