# 操作系统

## 学习目标与阅读方式

学完本章，应能沿“应用 → 系统调用 → 内核对象 → 内存/文件/设备”解释资源如何被隔离、共享和回收，并能：

- 区分进程、线程、协程以及运行、阻塞、僵尸等状态。
- 解释调度、同步、虚拟内存、页缓存、文件系统和 I/O 通知的稳定语义。
- 估算虚拟页数量、页表数量级、文件描述符与并发资源边界。
- 从 CPU、内存、文件和 I/O 证据链判断常见 Linux 问题。

建议先阅读计算机组成原理中的指令、Cache、中断和 DMA。本文负责操作系统概念、计算、案例与自测；调度、页表、VFS 和设备路径的内部状态见[硬件与操作系统核心机制](../07-核心机制深入/01-硬件与操作系统.md)。命令只作知识示例，本阶段不要求实际执行或制造故障。

## 基础知识

操作系统负责抽象和管理 CPU、内存、文件、设备与网络，并在隔离、共享和效率之间取舍。

### 用户态、内核态与系统调用

应用通常在受限的用户态执行，不能直接配置页表或设备。系统调用通过受控入口切换到内核态，由内核检查参数和权限后操作进程、文件、网络或设备，再返回用户态。

- 系统调用：应用主动请求内核服务，如 `read`、`write`、`mmap`。
- 异常：当前指令同步触发，如缺页、非法指令、除零。
- 中断：设备或定时器异步通知 CPU。

三者都可能进入内核处理代码，但来源、时机和返回语义不同。一次函数调用不一定是系统调用；语言库可以在用户态完成工作，也可能封装多个系统调用。

### 进程、线程与协程

- 进程：资源隔离和分配单位，拥有独立虚拟地址空间。
- 线程：进程内的执行单元，共享大部分进程资源，但有独立栈和寄存器上下文。
- 协程/goroutine：用户态调度的轻量任务，最终仍运行在线程上。

线程共享内存不等于线程安全。多个线程写同一状态时需要锁、原子操作、消息传递或避免共享。

程序是静态代码和数据；进程是程序的一次运行及其资源上下文。Unix/Linux 常通过 `fork` 创建带 COW 地址空间的子进程，再用 `exec` 替换为新程序。线程退出只结束执行单元；进程最后一个线程退出后，内核保留少量退出状态供父进程 `wait` 回收。

- 僵尸进程：已经退出，但父进程尚未读取退出状态；它不再执行，也不占完整地址空间。
- 孤儿进程：父进程先退出，子进程仍运行，之后由系统指定的收养者负责回收。
- 守护进程：长期后台运行的服务模式，不等同于孤儿或僵尸。

### 进程状态与调度

常见状态包括运行、可运行、睡眠、停止和僵尸。负载平均值在 Linux 中通常包含可运行任务以及不可中断睡眠任务，并不等同于 CPU 使用率。

上下文切换会保存与恢复执行状态。过多线程、锁竞争、频繁系统调用都可能增加切换成本。

调度器需要在吞吐、响应时间、公平、优先级和实时性之间取舍。常规调度会维护可运行任务及其运行时间/权重；定时器中断、任务阻塞、唤醒、时间配额或更高优先级任务可触发调度判断。具体算法随内核版本演进，不应把某个时间片或 CFS 实现细节当作永久接口。

- CPU 密集任务长时间需要执行单元；可运行数量持续超过可用 CPU 时会排队。
- I/O 密集任务经常睡眠等待设备或网络，更多并发可覆盖等待，但不能突破下游容量。
- 上下文切换包含寄存器与调度开销，并可能扰动 Cache/TLB；切换数高要结合吞吐和阻塞原因判断。
- nice/优先级改变竞争 CPU 时的权重，不会让单线程突破一个核心，也不能修复 I/O 瓶颈。

### 虚拟内存

每个进程看到独立虚拟地址空间，由页表映射到物理内存。核心机制包括：

- 分页与缺页异常。
- 按需分配和 copy-on-write。
- 文件映射和页缓存。
- swap 与内存回收。

Redis `fork` 做 RDB/AOF 重写时使用 copy-on-write；如果父进程大量写入，额外内存可能显著增加。

内存不足时，内核会在匿名页、文件页、脏页、swap 与进程回收之间取舍。`free` 中“available”通常比“free”更接近应用还能获得的内存，但它仍是估算。排查要同时观察 RSS、页缓存、major fault、swap in/out、内存压力和 OOM 记录。

#### 地址翻译与页数量估算

虚拟地址通常被拆成“多级页表索引 + 页内偏移”。TLB 缓存近期翻译；TLB miss 需要 page walk，页表项无有效映射且访问合法时可能触发缺页处理。

假设页大小为 4KiB：

```text
page_count = mapped_bytes / page_size
1GiB 连续映射需要 2^30 / 2^12 = 2^18 = 262144 个虚拟页
```

若每个页表项按 8B 粗估，仅最末级页表项约占 `262144×8 = 2MiB`；真实页表还有上级目录、页表页取整、稀疏映射、共享和架构差异。48 位地址也不表示每个进程立即分配覆盖全部地址空间的页表。

缺页类型要分开：minor fault 可在内存中完成映射，major fault 需要存储 I/O，COW fault 在首次写共享页时分配并复制。`mmap` 只建立地址空间关系，访问时是否读盘取决于页是否驻留。

### 文件与文件描述符

Linux 将文件、套接字、管道等抽象为文件描述符。连接数上限同时受进程限制、系统限制、内存和端口范围影响，不能只调 `worker_connections`。

删除仍被进程打开的文件不会立即释放磁盘空间，可用 `lsof +L1` 查找。

#### VFS 与文件对象

一次路径访问可概念化为：

```text
进程 fd 表 → 打开的 file 对象（偏移、标志）
→ dentry（目录项/名字缓存）→ inode（文件元数据）
→ 文件系统 → page cache/块层 → 设备
```

多个 fd 可以引用同一个 file 对象，也可以分别打开同一 inode 而拥有独立偏移；`dup`、`fork` 和重新 `open` 的共享关系不同。inode 表示文件对象而不是文件名，硬链接是多个目录项指向同一 inode。

fd 容量不是单一数字：

```text
effective_fd_capacity ≤ min(进程软/硬限制, 系统可分配文件对象, 内存与应用容量)
```

每个连接还可能占客户端 socket、上游 socket、日志或文件 fd，因此“10 万连接”等于“10 万 fd”并不总成立。

### I/O 模型

- 阻塞 I/O：调用等待操作完成。
- 非阻塞 I/O：未就绪立即返回。
- I/O 多路复用：一个线程等待多个描述符的就绪事件。
- 异步 I/O：提交操作，完成后收到通知。

`epoll` 是 Linux 的就绪通知机制，不会替应用完成业务计算。Nginx 的高并发来自事件循环、非阻塞套接字、少量 worker 和高效数据路径的组合。

“阻塞/非阻塞”描述一次调用在未就绪时怎样返回；“同步/异步”描述操作完成和结果交付方式。非阻塞 + epoll 通常仍是同步地执行 `read/write`，epoll 只通知“现在值得尝试”。真正的异步接口把操作提交给内核，之后取得完成结果。

`select`/`poll` 通常由应用重复提交或遍历关注集合；epoll 把关注关系保存在内核并返回就绪项，适合大量 fd 中少量活跃的场景。`io_uring` 提供共享队列式提交/完成接口，能降低部分系统调用和异步 I/O 成本，但安全限制、内核版本、操作类型和工作负载决定收益，不是 epoll 的无条件替代品。

#### epoll 的内部工作过程

典型调用分三步：

```text
epoll_create1()  → 创建 epoll 实例
epoll_ctl()      → 添加/修改/删除关注的文件描述符及事件
epoll_wait()     → 等待就绪事件并返回就绪列表
```

可把内核中的关键关系简化为：

```text
关注集合（interest list）        就绪队列（ready list）
fd 4: EPOLLIN  ───────┐
fd 7: EPOLLOUT ───────┼─ 设备/协议栈发现状态变化 → [fd 4, fd 9, ...]
fd 9: EPOLLIN  ───────┘                         ↓
                                            epoll_wait 返回
```

与每次把全部 fd 数组交给 `select` 扫描相比，epoll 把关注集合保存在内核中，应用主要取得已就绪事件。但实际复杂度还包含回调、就绪队列、锁和事件复制，不能简单宣传为所有操作绝对 `O(1)`。

#### LT 与 ET

- Level Triggered（LT）：只要条件仍满足，下次 `epoll_wait` 还会继续通知；更容易正确使用，是默认模式。
- Edge Triggered（ET）：主要在状态从未就绪变为就绪时通知；应用必须使用非阻塞 fd，并持续读/写直到返回 `EAGAIN`，否则可能留下数据却收不到新边沿。

ET 不必然更快。选择它是为了减少重复通知，并接受更复杂的正确性要求。

#### Nginx 动态请求示例

```text
客户端 socket 可读
→ worker 读取并解析 HTTP
→ FastCGI socket 暂不可写：注册写事件，继续处理其他连接
→ FastCGI 可写：发送请求
→ 等待 PHP-FPM 时 worker 处理其他事件
→ FastCGI 可读：读取响应
→ 客户端 socket 可写：发送响应
```

这里的“异步”指控制流被事件拆开推进；“非阻塞”指单次系统调用不会因未就绪长期挂住线程。PHP-FPM 执行业务本身仍可能阻塞，Nginx 只是没有陪它一起空等。

### 文件写入何时算完成

`write()` 成功通常只表示数据已复制到内核可管理的缓冲区，不等于已经持久化到介质。数据库和日志系统会根据一致性目标使用 `fsync`/`fdatasync`、WAL、校验与恢复协议。即便调用同步接口，最终保证仍与文件系统、挂载参数、设备缓存和硬件行为有关。

普通 buffered write 常先修改 page cache，脏页由后台 writeback；`fsync` 请求把文件所需数据和元数据推进到持久层。文件系统 journal 主要保护元数据或按模式保护部分数据的一致性，不等于自动保存应用事务。应用仍要定义写临时文件、同步、原子 rename、目录同步等崩溃协议。

## 高阶知识

### 同步、互斥与死锁

- 互斥锁保护临界区。
- 读写锁适合读多写少，但不一定总比互斥锁快。
- 信号量控制并发额度。
- 条件变量等待状态变化。
- 原子操作适合简单状态，不应硬拼复杂不变量。

死锁四个必要条件：互斥、持有并等待、不可抢占、循环等待。常见预防方式是固定加锁顺序、缩小事务与临界区、设置超时并避免持锁执行远程调用。

竞态条件表示结果依赖不可控的并发时序。互斥锁让临界区一次只有一个执行者；读写锁允许多个读者但会引入更复杂的公平和升级问题；信号量管理许可数量；条件变量必须配合受锁保护的谓词并在循环中重新检查；原子操作适合单个状态或经过证明的无锁协议。

CPU 缓存一致性不等于语言层内存顺序。锁和带内存序的原子操作既约束竞争访问，也建立规定的可见性顺序。仅把变量声明为“volatile”通常不能替代互斥或原子读改写，具体语义必须看语言规范。

处理死锁可以选择预防（固定顺序）、避免（仅在可判断安全状态时分配）、检测并恢复，或在可接受场景使用超时。超时能结束等待，但不证明共享状态仍然正确，恢复逻辑必须保证不变量。

### 内存回收与 OOM

匿名页通常来自堆、栈等，文件页由文件映射/page cache 支撑；干净文件页可丢弃后重读，脏页先写回，匿名页若要回收通常需 swap 或终止进程。内核会基于水位、活跃程度、脏页和 cgroup 限制进行回收。

内存压力可能表现为直接回收、频繁 major fault、swap 抖动和 OOM kill。OOM 选择受进程内存、`oom_score_adj`、cgroup 范围等影响。容器设置内存上限后，即使宿主机仍有内存，也可能在该 cgroup 内回收或 OOM。

### namespace、cgroup 与容器

容器共享宿主机内核：namespace 隔离进程号、网络、挂载、主机名、用户等视图；cgroup 统计和限制 CPU、内存、I/O、进程数等资源；分层/overlay 文件系统组织镜像与可写层。容器不是拥有独立内核的轻量虚拟机。

cgroup CPU quota 会让应用在墙上时间内被节流，即使它看到许多逻辑 CPU；内存限制会改变回收和 OOM 边界。运行时、JVM、Go 或 worker 数需要读取容器实际配额，而不能只按宿主机资源配置。

### Linux 资源观察

| 目标 | 常用工具 |
|---|---|
| 进程/线程 | `ps`, `top`, `pidstat` |
| 内存 | `free`, `vmstat`, `/proc/<pid>/status` |
| 磁盘容量 | `df`, `du` |
| 磁盘 I/O | `iostat`, `iotop` |
| 网络连接 | `ss`, `ip`, `tcpdump` |
| 打开文件 | `lsof` |
| 服务日志 | `journalctl` |

`df` 查看文件系统已分配空间，`du` 汇总目录可见文件大小；二者不一致可能来自已删除但仍打开的文件、挂载点或稀疏文件。

`ps -ef` 使用 POSIX 风格选项；常用 BSD 风格是 `ps aux`，不是把 `aux` 理解成 `-a -u -x` 的固定组合。

## 使用案例

### 估算地址空间与 COW 放大

4KiB 页下，进程实际修改 fork 后共享数据中的 600MiB，COW 最坏新增页数据约 600MiB，而不是整个虚拟地址空间。还要加页表、分配器碎片和并发新增写入；反之，只读页继续共享。Redis 后台保存时的内存峰值取决于子进程存活期间父进程实际修改的页。

### 查看 Nginx 服务日志

```bash
journalctl -u nginx
journalctl -u nginx --since "1 hour ago"
journalctl -u nginx -f
```

`journalctl` 查询 systemd journal；`-u nginx` 按 systemd unit 过滤。应用自有 access/error log 仍需单独查看。

### 查看某进程资源

```bash
ps -p "$PID" -o pid,ppid,%cpu,%mem,rss,vsz,stat,etime,cmd
pidstat -p "$PID" 1
lsof -p "$PID"
```

### 验证文件描述符与 epoll 压力

```bash
cat /proc/$PID/limits
ls /proc/$PID/fd | wc -l
cat /proc/sys/fs/file-nr
ss -s
```

连接容量要同时考虑进程 fd 限制、系统 fd、每连接内存、监听队列、上游连接和应用容量。只提高 `ulimit -n` 不能解决下游已经饱和的问题。

## 常见问题与排查

| 现象 | 不要直接下结论 | 建议证据链 |
|---|---|---|
| load average 高 | 不等于所有 CPU 满载 | 可运行任务、不可中断睡眠、每核使用率、I/O 等待 |
| free 内存很少 | 不等于内存泄漏 | available、RSS、page cache、swap、fault、内存压力 |
| 进程 CPU 高 | 不等于代码纯计算 | 用户/内核时间、线程热点、系统调用、软中断、锁等待 |
| df 满但 du 对不上 | 不只看目录文件 | 已删除仍打开文件、挂载点、稀疏文件、预留空间 |
| fd 耗尽 | 不只提高 ulimit | 进程/系统限制、泄漏、连接生命周期、每请求 fd 数 |
| D 状态多 | 不要直接 kill | 具体等待通道、块设备延迟、网络存储、内核日志 |

### 端口占用

```bash
ss -lntp '( sport = :80 )'
```

先识别占用者，再决定停止服务或修改端口。不要直接杀进程后假设问题解决；systemd 可能自动拉起它。

### 磁盘满

1. `df -h` 确认文件系统。
2. `du -xhd1 <mount>` 定位目录。
3. `lsof +L1` 查找已删除仍打开文件。
4. 通过 logrotate、保留策略或扩容解决，不直接删除正在写入的日志。

### 内存不足

检查 OOM 日志、RSS 增长、swap、页缓存和并发峰值。先找分配者和增长原因，再调整进程数或内存限制。

## 常见误区

1. **进程是执行单位、线程是资源单位**：常见 Linux 语境下进程承载资源视图，线程才是可调度执行实体，但实现会共享多种内核对象。
2. **协程不使用线程**：协程最终仍由线程在 CPU 上执行。
3. **load average 就是 CPU 使用率**：Linux 还通常计入不可中断睡眠任务。
4. **虚拟内存就是 swap**：虚拟内存包含地址空间、页表、按需映射、文件映射和 COW，swap 只是可能的后备。
5. **VSZ 等于实际占用内存**：RSS、共享页、按需映射和 cgroup 口径都不同。
6. **write 成功即永久落盘**：通常只到内核缓冲，持久化还涉及同步、文件系统与设备。
7. **epoll 本身完成异步读写**：它主要通知就绪，应用仍调用读写。
8. **ET 一定比 LT 快**：ET 以更复杂的正确性要求换取减少部分重复通知，收益取决于负载。
9. **加大 fd 上限就能提高连接容量**：内存、端口、队列、上游和业务吞吐也会限制。
10. **容器拥有自己的 Linux 内核**：普通容器共享宿主机内核，由 namespace/cgroup 提供隔离和限制。

3. 僵尸进程保留什么？为什么 `kill -9` 不能直接清除它？
4. 8 核机器有 16 个持续可运行的 CPU 密集线程意味着什么？
5. 4KiB 页下映射 2GiB 地址需要多少虚拟页？若末级页表项 8B，末级表项约占多少？
6. minor fault、major fault 和 COW fault 有何区别？
7. inode、dentry、file 对象和 fd 分别代表什么？
8. write、writeback、fsync 和 journal 分别处在哪个边界？
9. 非阻塞 I/O、epoll 就绪通知和真正异步 I/O 有何区别？
10. 宿主机仍有空闲内存时，容器为什么仍可能 OOM？

### 参考答案

1. 系统调用由应用主动请求；异常由当前指令同步触发；中断通常由外部设备或定时器异步触发。
2. 进程提供地址空间和资源上下文，内核调度线程，用户态运行时调度协程到线程；同进程线程共享多数资源。
3. 保留 PID、退出码和少量统计供父进程 wait；僵尸已经退出，无可再杀，需父进程或收养者回收。
4. CPU 供给最多约 8 个核，线程持续竞争并排队；吞吐是否接近上限还取决于 IPC、频率和共享资源。
5. `2^31/2^12=2^19=524288` 页；末级表项约 `524288×8=4MiB`，未计上级、取整和架构差异。
6. minor 无需存储 I/O，major 需从存储载入，COW 在首次写共享页时复制。
7. inode 是文件元数据对象，dentry 关联名字与 inode，file 保存一次打开的偏移/标志，fd 是进程表中的整数引用。
8. write 常写入 page cache，writeback 异步下刷，fsync 请求必要数据持久化，journal 保护文件系统一致性而非自动提供应用事务。
9. 非阻塞表示未就绪立即返回；epoll 返回值得尝试的 fd；异步 I/O 提交操作后通过完成事件取得结果。
10. cgroup 内存上限形成独立回收/OOM 边界，容器可用量不等于宿主机全局空闲量。
