# 故障排查手册

## 通用方法

```text
确认影响范围
→ 建立时间线
→ 获取可复现证据
→ 按层定位
→ 先止损
→ 修复根因
→ 验证恢复
→ 复盘和预防
```

不要一开始就重启、扩容或修改多个参数。重启可能清除证据，多项修改会让结果无法归因。

## 第一层：用户与入口

确认：哪个用户、哪个接口、何时开始、全部还是部分、成功率和延迟分位数。保存 request_id、状态码和错误消息。

```bash
curl -v --connect-timeout 3 --max-time 10 https://example.com/health
dig example.com
```

## 第二层：负载均衡与 Nginx

检查：

- DNS/证书/监听端口。
- Nginx active connections、状态码和 request time。
- error log 的 upstream 错误。
- 配置是否通过 `nginx -t`，实际生效配置用 `nginx -T`。

| 现象 | 首要检查 |
|---|---|
| 404 | location、root/alias、rewrite、应用路由 |
| 413 | client body 大小限制和上游限制 |
| 499 | 客户端或上游代理提前断开 |
| 502 | 上游连接/协议/进程/socket 权限 |
| 504 | 上游超时、慢查询、外部依赖 |

## 第三层：应用进程

### PHP-FPM

- pool active/idle/max active。
- listen queue 是否增长。
- `pm.max_children` 是否达到。
- slowlog 和请求超时。
- worker RSS 与机器内存。

增大 worker 前先确认数据库连接池、CPU 和内存可承受。

### Go

- goroutine 数、阻塞点和泄漏。
- CPU/heap/mutex/block profile。
- GC 与 STW。
- context 是否按请求取消。
- HTTP response body 是否关闭。

## 第四层：数据与组件

### MySQL

查看慢 SQL、活跃事务、锁等待、连接数、Buffer Pool、磁盘和复制。若 CPU 高，找扫描行数和高频 SQL；若延迟高，区分锁、I/O、执行计划和连接等待。

### Redis

查看内存、eviction、命中率、延迟、慢命令、fork、复制和网络。禁止在大实例生产高峰直接执行 `KEYS *`；使用 `SCAN` 也要限速。

### Kafka/队列

查看 lag、最老消息年龄、失败率、重试 Topic、消费者状态和下游容量。扩消费者前确认分区数和数据库余量。

### Elasticsearch

查看集群健康、分片分配、JVM heap、磁盘水位、拒绝数、慢查询和 merge。

## 资源问题

### CPU

```bash
top -H -p "$PID"
pidstat -u -w -p "$PID" 1
```

区分业务计算、系统调用、上下文切换、GC、加密/压缩和虚拟机 steal。

### 内存

```bash
free -h
vmstat 1
ps -p "$PID" -o pid,rss,vsz,%mem,cmd
```

判断是进程堆、共享内存、页缓存、文件映射还是 swap；用趋势而非单点判断泄漏。

### 磁盘

```bash
df -h
df -i
du -xhd1 /var
lsof +L1
iostat -xz 1
```

同时检查容量、inode、已删除未释放文件和 I/O 延迟。

### 网络

```bash
ss -s
ss -lntp
ip route
tcpdump -ni any host 192.0.2.10
```

检查重传、连接队列、TIME_WAIT、丢包、路由和 MTU。不要只凭 ping 正常判断 HTTP 服务正常。

## 止损原则

- 限流和关闭非核心入口。
- 熔断故障依赖，返回可接受降级。
- 暂停高成本后台任务。
- 回滚最近发布或配置。
- 扩容只作为确认瓶颈后的临时/长期措施。

涉及数据时先备份和确认恢复路径，不执行不可逆清理。

## 故障复盘模板

1. 用户影响与持续时间。
2. 检测方式和为何没有更早发现。
3. 精确时间线。
4. 技术根因和组织/流程促成因素。
5. 止损与恢复动作。
6. 哪些动作有效、哪些无效。
7. 带负责人和期限的改进项。
8. 如何验证改进已生效。
