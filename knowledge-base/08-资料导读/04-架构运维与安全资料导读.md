# 架构、运维与安全资料导读

## 1. 设计模式

- [PHP 设计模式案例](../../learning-materials/04-分布式与架构/design-patterns-php/)
- [Java 设计模式案例](../../learning-materials/04-分布式与架构/java-design-patterns/)

先识别变化点和耦合，再选择模式。策略、适配器、装饰器、观察者、命令和状态模式应配合真实需求学习；不要为了使用模式增加无意义接口和工厂。

## 2. 系统设计与 API

- [System Design Primer](../../learning-materials/04-分布式与架构/system-design-primer/)：容量、缓存、复制、分区和典型系统案例。
- [System Design 101](../../learning-materials/04-分布式与架构/system-design-101/)：图解辅助，属于三级来源。
- [Azure Architecture Center](../../learning-materials/04-分布式与架构/architecture-center/)：云架构模式、可靠性和案例。
- [OpenAPI Specification](../../learning-materials/04-分布式与架构/openapi-specification/)：HTTP API 契约标准。

设计顺序固定为：目标与 SLO → 流量和容量 → 数据与一致性 → 单点和故障域 → 限流背压 → 可观测性 → 成本。组件名称不能代替约束分析。

## 3. 分布式协调与消息

- [etcd 官方文档](https://etcd.io/docs/)、[ZooKeeper 官方文档](https://zookeeper.apache.org/doc/current/)：共识、线性一致读写、租约、watch 和成员变更。
- [Nacos 官方文档](https://nacos.io/docs/latest/overview/)：服务发现和配置管理。
- [RocketMQ 官方文档](https://rocketmq.apache.org/docs/)：消息存储、消费和容错实现。

这些产品的完整源码不在知识库本地保存；需要追踪实现时再从官方仓库按版本获取。

高阶学习必须覆盖网络分区、时钟、脑裂、选主、日志复制、法定人数和恢复，而不是只学习客户端调用。

## 4. 容器与 Kubernetes

- [Docker 官方文档](../../learning-materials/05-运维可观测性与安全/docker-docs/)
- [Kubernetes 官方文档](../../learning-materials/05-运维可观测性与安全/kubernetes-website/)

先理解 namespace、cgroup、镜像分层和容器进程，再学习 Pod、Deployment、Service、Ingress、配置、存储、探针、调度和资源限制。容器不等于虚拟机，Kubernetes 也不会自动修复错误的应用状态。

## 5. 可观测性与安全

- [Prometheus 文档](../../learning-materials/05-运维可观测性与安全/prometheus-docs/)：指标、PromQL、规则和告警。
- [OpenTelemetry 文档](../../learning-materials/05-运维可观测性与安全/opentelemetry-docs/)：trace、metric、log 的采集和上下文传播。
- [OWASP Cheat Sheet](../../learning-materials/05-运维可观测性与安全/owasp-cheat-sheets/)：认证、会话、输入验证、密码、上传、SSRF、SQL 注入等安全实践。

可观测性围绕用户症状、SLO、RED/USE 指标和证据链设计；安全围绕资产、信任边界、攻击面、最小权限和审计设计。

## 6. 验收

1. 为一个 Web 服务写出容量估算、SLO、依赖超时预算和故障域。
2. 制造实例退出、依赖超时、消息积压和网络分区，验证恢复策略。
3. 用指标发现问题、trace 定位链路、日志确认上下文。
4. 用 OWASP 清单审查认证、会话、上传和服务端请求边界。
