# 版本矩阵与迁移路线

## 总原则

知识库同时服务遗留项目和新项目。旧版本不会删除，但必须标记支持状态；新版本不能反向覆盖旧版本真实行为。

| 技术 | 遗留/存量 | 主要学习版本 | 补充方向 | 重点差异 |
|---|---|---|---|---|
| MySQL | 5.7 | 8.0 | 8.4 LTS | 数据字典、字符集、认证、SQL 特性、优化器、复制 |
| PHP | 7.4 | 8.2/8.3 | 8.4 | 类型系统、错误模型、弃用、JIT、扩展兼容 |
| Linux | 4.x/早期 5.x | 5.10/6.1 | 6.6 及后续 LTS | 调度、I/O、网络、cgroup、eBPF；按发行版回移核对 |
| Redis | 5/6.2 | 7.x | 8.x | listpack、I/O、多线程任务、持久化、Cluster、安全默认值 |
| Elasticsearch | 2.x/6.x | 7.17/8.x | 新主版本 | type 移除、mapping、查询、发现、安全、客户端兼容 |
| Kafka | 旧 ZooKeeper 模式 | 3.x | 4.x/KRaft | 元数据管理、协议、消费者组、幂等与事务 |
| RabbitMQ | 旧经典镜像队列 | 3.12/3.13 | 4.x | quorum queue、特性标志、弃用项、升级路径 |
| Node.js | 0.x/12/14/16 | 20/22 | 24 | ESM、Web API、运行时权限、依赖兼容 |
| Apache HTTPD | 2.2 | 2.4 | 当前稳定版 | 访问控制、模块、TLS 和配置语义 |
| Nginx | 早期 1.x | 近年稳定版 | 当前 mainline | HTTP/2/3、TLS、模块和弃用指令 |
| 前端 | AngularJS/jQuery | Vue 3/React | Web Components | 模块化、响应式、构建与浏览器标准 |

## MySQL 迁移阅读顺序

1. 先用 5.7 手册确认旧系统当前行为和参数。
2. 阅读 8.0 升级章节，列出不兼容 SQL、字符集、认证插件和配置。
3. 在副本或脱敏数据上执行升级检查、回归测试和性能基线。
4. 再评估 8.4 LTS，不跨版本猜测默认值。

## TCP/IP 的“版本”处理

TCP/IP 按 RFC 和实现演进组织，不采用产品式版本号：

- TCP 核心语义：RFC 9293。
- 拥塞控制：RFC 5681。
- Window Scale 与 Timestamp：RFC 7323。
- SACK：RFC 2018。
- RTO：RFC 6298。
- QUIC：RFC 9000；HTTP/3：RFC 9114。

实验必须记录 Linux 内核、拥塞控制算法、网络时延、丢包和带宽；否则“窗口大小”和“吞吐”数字不可复现。

## Linux 的“版本”处理

系统调用、虚拟内存、VFS、进程和网络栈等原理使用稳定主线讲解；具体结构体、内核参数和观测工具按目标发行版内核核对。发行版可能回移新功能和安全修复，不能只用主版本号推断行为。

## 升级验收模板

1. 记录当前版本、插件、配置和数据格式。
2. 列出官方不兼容变化与已停止支持功能。
3. 建立功能、性能、故障恢复和回滚基线。
4. 在隔离环境升级并保存证据。
5. 灰度发布，监控错误率、延迟、资源和数据一致性。
6. 达到观察窗口后再移除旧版本回滚路径。
