# 数据库与中间件资料导读

## 1. MySQL

### 完整官方手册

- [MySQL 5.7 Reference Manual](../../learning-materials/03-数据库与中间件/mysql-5.7-manual/refman-5.7-en.pdf)：遗留项目。
- [MySQL 8.0 Reference Manual](../../learning-materials/03-数据库与中间件/mysql-8.0-manual/refman-8.0-en.pdf)：主要学习和生产参考。
- [MySQL 8.4 Reference Manual](../../learning-materials/03-数据库与中间件/mysql-8.4-manual/refman-8.4-en.pdf)：LTS 补充。
- [MySQL Server 官方源码](https://github.com/mysql/mysql-server)：仅在需要追踪实现时按需获取，不在知识库保存完整副本。

### 学习主线

SQL 与关系模型 → 页和记录 → B+ 树索引 → Buffer Pool → redo/undo/binlog → MVCC 与锁 → 优化器 → 复制与备份恢复。

页大小和树高必须通过配置与参数计算：默认 InnoDB 页通常为 16 KiB，但可受初始化配置影响；扇出由页可用空间、键长度、指针和记录开销共同决定。树高估算使用 `容量 ≈ 叶子记录数 × 内部节点扇出^(层数-1)`，再用真实页统计验证。

## 2. Redis 与 Memcached

- [Redis 官方文档](../../learning-materials/03-数据库与中间件/redis-docs/)：数据类型、持久化、复制、Cluster 和运维。
- [Memcached 官方站点](https://memcached.org/)与[源码](https://github.com/memcached/memcached)：按需查询协议和实现，不在知识库保存完整源码。

学习重点不是命令表，而是缓存穿透、击穿、雪崩、一致性、热 key、大 key、过期和淘汰。Redis 版本要区分 ziplist/listpack、I/O 线程、持久化和集群行为。

## 3. Elasticsearch 与 MongoDB

- [Elastic 官方文档](../../learning-materials/03-数据库与中间件/elasticsearch-docs/)：索引、映射、查询、聚合、分片和集群运维。
- [MongoDB 官方文档](../../learning-materials/03-数据库与中间件/mongodb-docs/)：文档模型、索引、复制集、分片和事务。

Elasticsearch 旧版资料要明确版本；type、mapping、查询 DSL、集群发现和安全默认值不能从 2.x 直接套到 7.x/8.x。

## 4. 消息队列

- [Apache Kafka 官方文档](https://kafka.apache.org/documentation/)：学习日志、分区、副本和生产消费协议；源码仅在追踪实现时按需获取。
- [RabbitMQ 官方文档](../../learning-materials/03-数据库与中间件/rabbitmq-documentation/)：exchange、queue、binding、确认、死信、仲裁队列和故障恢复。

统一问题模型：顺序范围、投递语义、重复处理、幂等、重试、死信、积压、背压、再均衡和故障转移。不要用“绝对不丢、绝对不重”代替端到端约束。

## 5. RPC

- [gRPC 官方文档](../../learning-materials/03-数据库与中间件/grpc-documentation/)
- [Apache Thrift 官方文档](https://thrift.apache.org/docs/)

重点比较 IDL、兼容性、序列化、连接复用、超时、取消、重试和流式调用。RPC 框架不能自动解决幂等、雪崩和跨服务事务。

## 6. 推荐实验与验收

1. 计算并验证 MySQL 索引树高、Buffer Pool 命中率和一次事务的日志链路。
2. 构造 Redis 热 key、大 key、缓存击穿和主从切换。
3. 验证 Elasticsearch 分片数变化对写入、查询和恢复的影响。
4. 让 Kafka/RabbitMQ 消费者在提交前后崩溃，观察重复和丢失边界。
5. 为 RPC 设置逐层超时、取消和幂等键，并验证失败传播。
