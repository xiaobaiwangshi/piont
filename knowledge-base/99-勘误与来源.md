## 重要勘误

| 原始资料中的常见表述 | 整理后的结论 |
|---|---|
| 现代 IP 仍以 A/B/C 类划分为主 | 现代网络使用 CIDR；分类地址只作历史知识 |
| TLS 用证书公钥加密随机数就是完整握手 | 现代 TLS 1.3 通常用（EC）DHE 协商并提供前向保密 |
| HTTP/2 Server Push 是推荐优化 | 主流浏览器已移除/停用，优先缓存和 preload |
| 链表插入/删除总是 O(1) | 只有已定位节点时 O(1)，查找位置可能 O(n) |
| 哈希表的 Hash 函数示例直接等同 MD5/SHA | 数据结构哈希与密码学哈希目标不同 |
| PHP 正则支持 `g` 修饰符 | PHP PCRE 没有 JavaScript 式 `g`；全局匹配用 `preg_match_all` |
| Go map 的值必须可比较 | map 的键必须可比较，值可以是 slice/map 等任意类型 |
| Go 内嵌等同继承 | 内嵌是组合和方法提升，不建立父子类型关系 |
| Gin `Get`、`bind`、`ShouldBindUrl` 等 | 正确 API 需按版本核对，如 `GET`、`ShouldBind`、`ShouldBindUri` |
| MySQL 8 查询先查 query cache | MySQL 8.0 已移除 query cache |
| `IS NULL`、范围、`!=` 必然索引失效 | 是否使用索引取决于计划、分布和成本 |
| 两阶段锁减少死锁 | 它保证冲突可串行化，但持锁等待可能产生死锁 |
| Redis 完全单线程 | 命令执行大多串行；网络 I/O、后台任务可使用线程/子进程 |
| Redis Cluster 有 16348 槽 | 正确为 16384 槽 |
| Redis `MULTI/EXEC` 像 MySQL 一样失败回滚 | 命令不会被插入，但运行期错误不回滚已执行命令 |
| Redis 小结构固定使用 ziplist 和固定阈值 | 新版本使用 listpack 等，阈值与版本/配置相关 |
| `preset` 越慢导致播放端同等变慢 | preset 主要影响编码成本和压缩效率，解码影响不等比例 |
| HLS `split_by_time+independent_segments` 总是正确 | 非关键帧切分可能与独立分片语义冲突 |
| 二次加密 HLS key 可防止合法客户端提取 | 客户端最终需明文/可用 key，只能提高成本，不能绝对防盗 |
| `/dev/vdb1` 挂载但格式化 `/dev/vdb` | 分区、格式化和 fstab 目标必须一致，并先确认设备 |
| Nginx FastCGI 中使用 `proxy_set_header` | FastCGI 使用 `fastcgi_param`；proxy 指令用于 HTTP 代理 |
