# 核心知识主线融合设计

## 目标

把 `raw_doc_` 中仍然有效的基础知识，与 `learning-materials/` 中较新的开放教材和官方文档交叉验证后，融合进现有 `knowledge-base/`。最终产物应是可以按“基础 → 原理 → 案例 → 排障 → 验收”连续学习的中文教程，而不是来源文件摘要或链接集合。

## 边界

- `raw/`、`raw_doc/`、`raw_doc_/`、`raw_llm/` 等原始资料只读，不改名、不转换覆盖、不删除。
- `learning-materials/` 是核对来源，不是最终阅读入口。
- `knowledge-base/` 是唯一学习入口，允许补充和改写此前生成的整理文档。
- 不全文翻译、搬运或拼接书籍；只提炼概念、推导、案例和问题模型，并重新组织表达。
- 第一阶段覆盖：计算机组成、网络、操作系统、数据结构与算法、Web 请求、PHP/Go、LNMP、MySQL、Redis、Elasticsearch、Kafka/消息队列。
- 设计模式、系统架构、容器、安全和可观测性只补充与第一阶段直接相连的内容，完整深化留到后续阶段。

## PDF 处理策略

本机 Poppler 位于 `/usr/local/bin`：

- `pdfinfo`：建立文件、页数和页面尺寸清单。
- `pdftotext`：优先处理带文本层的 PDF。
- `pdftoppm`：扫描型 PDF 只渲染目录页和目标章节，不做全书 OCR。
- 中文 Tesseract 数据当前不可用，因此不把低质量自动 OCR 当作正文来源；扫描页通过清晰 PNG 定向阅读。

实测 `计算机网络.pdf` 共 464 页，前 10 页文本层仅产生 10 字节换页符，但第 8 页可渲染为清晰的 829×1234 PNG，证明扫描型资料可按目标页处理。

## 内容融合结构

每个核心章节沿用统一结构：

1. 基础知识：术语、模型和最小因果链。
2. 核心机制：数据如何流动、状态如何变化、成本在哪里产生。
3. 定量推导：窗口、吞吐、延迟、页大小、B+ 树扇出、缓存容量等可计算内容。
4. 使用案例：最小命令、配置、SQL 或伪代码。
5. 解决问题：现象 → 假设 → 证据 → 定位 → 修复 → 验证。
6. 版本边界：区分稳定原理、版本默认值和已废弃做法。
7. 学习验收：解释题、计算题、实验和故障演练。
8. 来源：指向原始资料名称、官方文档或 RFC，不复制大段原文。

基础章节负责建立完整路线；`07-核心机制深入/` 只保留需要推导、源码视角或实验验证的深入内容，避免同一知识重复两遍。

## 处理流程

1. 为每本资料建立主题与页码索引，标记文本型或扫描型。
2. 按目标章节抽取相关内容，不按书籍顺序生成摘要。
3. 将候选知识分为稳定原理、版本相关、过时或存疑四类。
4. 稳定原理与现有知识合并；版本内容用官方资料校正；过时内容只在“版本边界”中说明；存疑内容不写入正文。
5. 更新章节内链、学习路线和来源索引，使 `knowledge-base/README.md` 成为唯一入口。

## 验收

- 原始目录的文件数量、大小和校验值不因融合发生变化。
- 第一阶段每个主题至少包含基础、机制、案例、排障、版本边界和验收。
- TCP 滑动窗口与拥塞控制、InnoDB 页与 Buffer Pool、B+ 树扇出与树高等核心问题包含公式、假设和算例。
- 所有固定数字注明版本、配置或测量条件。
- Markdown 本地链接全部有效；代码块和命令可做静态检查。
- 每个新增结论能追溯到原始资料、官方文档、开放教材或可复现实验。
